## PART 2 — Authentication

### Step 2.1 — Auth flow implementation

Verify and fix each auth flow. For each one:
- Use the shared supabase client (never a local instance)
- Destructure { data, error } from every auth call
- If error !== null, surface it to the user via the UI — no silent catch/ignore
- Show a loading state (spinner or disabled button) during every async auth call

Flows to fix:

[ ] Registration — supabase.auth.signUp({ email, password, options: { data: { role } } })
     On success: show "Check your email to verify your account"
     On error: show exact Supabase error message

[ ] Login — supabase.auth.signInWithPassword({ email, password })
     On success: call router.push('/dashboard') or equivalent
     On error: show "Invalid email or password" — never expose raw error codes

[ ] Logout — supabase.auth.signOut()
     On success: clear all local/session storage and redirect to /login
     On error: still clear client state and redirect

[ ] Forgot Password — supabase.auth.resetPasswordForEmail(email, { redirectTo })
     Show success message regardless of whether email exists (security best practice)

[ ] Password Reset — supabase.auth.updateUser({ password: newPassword })
     Requires the user to be in a PASSWORD_RECOVERY session
     Validate: new password ≥ 8 chars before calling

[ ] Email Verification — Handle SIGNED_IN event with provider: 'email'
     in the auth state change listener

### Step 2.2 — Session management

In the root auth provider/context:
- Subscribe to supabase.auth.onAuthStateChange((event, session) => {})
- Handle these events explicitly: SIGNED_IN, SIGNED_OUT,
  TOKEN_REFRESHED, PASSWORD_RECOVERY, USER_UPDATED
- On SIGNED_OUT: wipe all user state from context/store immediately
- On TOKEN_REFRESHED: silently update the session — no user-visible action
- Call supabase.auth.getSession() on mount to restore session after
  browser refresh — do NOT assume the user is logged out on refresh

### Step 2.3 — Route protection

- <ProtectedRoute>: redirect to /login if session === null
- <AdminRoute>: redirect to /unauthorized if session.user.app_metadata.role !== 'admin'
- While session is loading (isLoading === true), render a full-page
  skeleton — never flash the login page to authenticated users
- Read role from app_metadata, NOT user_metadata
  (user_metadata is user-editable; app_metadata is server-side only)

## PART 4 — Realtime Subscriptions

### Step 4.1 — Fix all realtime hooks

For every hook that uses supabase.channel():

- Use the shared client from src/lib/supabase/client.ts
- Channel name must be unique and descriptive: e.g. realtime:countries:list
- Always return a cleanup function from useEffect:
  return () => { supabase.removeChannel(channel) }
- Never create a channel inside a render loop — only inside useEffect
- Log subscription status: on SUBSCRIBED, CHANNEL_ERROR,
  TIMED_OUT, CLOSED

Hooks to fix (at minimum):

[ ] useRealtimeCountries — subscribe to INSERT/UPDATE/DELETE on countries
[ ] Realtime dashboard metrics — subscribe to relevant tables for live counters
[ ] Session updates — subscribe to session-related events
[ ] Notifications — subscribe to a notifications table filtered by
     user_id = auth.uid()

### Step 4.2 — Reconnection handling

In the root of the app or a dedicated RealtimeProvider:
- Listen to window online/offline events
- On online: call supabase.realtime.connect() and re-subscribe
  active channels
- Show a non-blocking UI banner when the connection is lost
